# Heckle

> **AI fan personalities you own as INFTs — heckle live events with takes logged to 0G Storage and reputation that travels with the character.**

Mint an AI fan personality as an **ERC-7857 INFT** on **0G mainnet**, attach it to a live event, and
watch it fire off in-character "takes" — each one generated by **TEE-attested 0G Compute**, stored on
**0G Storage**, and committed **on-chain**. Sell the character and its entire take history + reputation
travel with the token.

- **Live:** **https://tryheckle.xyz**
- **Deployer / character-seller agent:** [`0xbF7EF900…14Bf31`](https://chainscan.0g.ai/address/0xbF7EF900E2dB365455B91Fb133f78Fc70114Bf31)
- **Zero Cup:** Heckle is competing as **R32 #15 (Heckle vs Hanami)** and runs the tournament itself as an on-chain event (**event ID 2**).
- **Status:** Live on 0G mainnet (chainId **16661**). All four 0G primitives load-bearing — strip any one and Heckle stops being Heckle.

- **48 TEE-attested takes** across all 16 R32 matchups (3 characters × 16), every one `valid: true`
- **Verified receipt row** on every take — Stored root + Committed tx + attestation badge
- **Inline blob viewer** at [`/storage/[root]`](https://tryheckle.xyz/storage/0xee27109152c63934180319a82f4af4264bd32cab156213f9619f20687d2f62a3) — no raw gateway downloads
- **HeckleBrackets** contract for user prediction-set commits

## The 0G stack — load-bearing per primitive

| Primitive | What it does in Heckle | Strip it and… |
|---|---|---|
| **0G Chain** | Four contracts on 0G mainnet hold every mint, attachment, take commitment, reputation update, and user bracket: `HeckleCharacters`, `HeckleEvents`, `HeckleTakes` (reputation lives here — `reputationOf` / `gradePrediction`), `HeckleBrackets`. | nothing settles; characters aren't ownable, brackets aren't provable. |
| **0G Compute** | Every take is generated by a TEE-verifiable (`TeeML`) provider via the Direct broker; the response signature recovers to the provider's on-chain `teeSignerAddress`. | no provable, attested takes — just an unaccountable LLM. |
| **0G Storage** | Every take blob, personality blob, event-metadata blob, and bracket prediction-set is on Storage, retrievable by Merkle root. | takes can't be replayed or audited; history can't travel with the token. |
| **ERC-7857 INFTs** | The character *is* the token — ownership, take history, and reputation are all token-bound. | characters can't be assets. |

## Verify anything, don't trust us

- **Every take has a Storage root** — click any receipt row to open the blob in the in-app viewer.
- **Every take has an on-chain commit tx** — verify it on [chainscan](https://chainscan.0g.ai).
- **Every attestation is offline-reverifiable** — `ethers.verifyMessage(signedText, signature)` returns the provider's on-chain-registered TEE signer.

**Worked example — The Pundit's R32 #1 call (GoalGhost over Soul):**

- Blob: [`/storage/0xee2710…2f62a3`](https://tryheckle.xyz/storage/0xee27109152c63934180319a82f4af4264bd32cab156213f9619f20687d2f62a3) (raw: [Storage gateway](https://indexer-storage-turbo.0g.ai/file?root=0xee27109152c63934180319a82f4af4264bd32cab156213f9619f20687d2f62a3))
- `inferenceAttestation.valid` → **true**
- `recovered` = `0x2E79315804e7C8712afcEbF0E31F08174409D806` = the provider's on-chain `teeSignerAddress` — the signature was produced inside the TEE, not by us.

Reputation is not a separate deployment — it's a load-bearing subsystem inside `HeckleTakes`
(the `Reputation` struct, `reputationOf`, and `gradePrediction`). Addresses are baked into
`@heckle/shared` as defaults, so a fresh clone connects to the live contracts with zero config.

Per-user cost to commit a bracket: **~0.00076 0G** (one `commitBracket` tx; the storage upload is
sponsored server-side).

## Running locally

```bash
git clone --recurse-submodules https://github.com/winsznx/heckle
cd heckle
git submodule update --init --recursive   # Foundry deps (forge-std, OpenZeppelin), if not already

pnpm install
pnpm contracts:test          # 13 Foundry tests (6 core + 7 HeckleBrackets)
pnpm dev                     # http://localhost:3000 — connects to live mainnet contracts by default
```

The inference agent and contract (re)deploys need a funded 0G wallet — see **[DEPLOY.md](./DEPLOY.md)**.

## What's not in scope for R32

Honest boundaries:

- **Multi-user real-time bracket voting** — single-user on-chain bracket commits work today; live head-to-head voting is R16 (Tier 2).
- **Season system + public event registry** — curated events only for now; the open registry is R8 work.
- **Cross-round auto-population** — R32 winners are a manual data update when results announce (Jul 3); auto-advancing the bracket as results land is R16 polish.
